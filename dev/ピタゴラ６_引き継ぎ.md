ソースはリポジトリ `sorafjah/pitagora6` にあるので、`index.html` の添付は不要です（Claude がリポジトリを読みます）。

## 1. いまの状態

- ピタゴラスイッチ風の3Dゲーム。**床の上**（斜め上から見下ろす）にパーツを並べて玉をゴールへ運ぶ。壁に貼る版「ピタゴラ５」（sorafjah/pitagora5）の兄弟作。
- 公開先：https://sorafjah.github.io/pitagora6/ （main の `index.html`）
- 画面右上の表記 `v2026-11-15 ピタゴラ６-6` が最新版。
- スマホ対応（説明パネル・ホーム画面から全画面表示、スマホ横のゲーム画面の圧縮）は `head.html` の `@media` の中と、`ui.js` の `PHONE_L`（同じ条件の matchMedia）だけで効く。**iPadには影響しない作り。今後の変更でこれを消さないこと。**

### 画面の流れ（2026-11-15 に作り直し）

- **最初のページ（タイトル画面 `#home`）**：「ピタゴラ６」と4つの大きなカード。左上に「？」（モード全体の説明）。
  - 🔰 れんしゅう（レベル1・2・3。クリアすると ⭐）
  - 👀 みる
  - 🛠️ つくる（もとの「じゆう」。最初はみほん入り）
  - 🔧 なおして ゴール（かんたん＝1こ・ふつう＝2こ・むずかしい＝3こ ぬける）
- モードに入ると、そのモード用の説明画面が出る（「はじめる」で閉じる）。
- ゲーム画面の上のレベルタブとタイトルは外した。左上に小さな「🏠」（最初のページへ）と「？」（そのモードの説明）だけ。お題の文はその右。
- 最初のページを出している間は3Dの描画を止めている（iPadの負担を減らすため）。

## 2. ソースの場所と作業の仕方

`index.html` は `dev/` の5つの部品をつなげたもの。**編集は `dev/` の部品で行い、`dev/build.sh` で `index.html` を作る。**

| ファイル | 中身 |
|---|---|
| `dev/head.html` | HTMLの枠・CSS・説明画面のわく・タイトル画面・「つくっています…」（スマホ用CSSもここ） |
| `dev/sim.js` | `CFG`、`BOARD`（床 28×18）、`PARTS`、`createFloorSim`（物理。Node でも動く） |
| `dev/levels.js` | `LEVELS`（0〜2 れんしゅう、3 つくる、4 みる、5 なおして ゴール）、`SAMPLE`、`FREE_EMPTY`、`SHOWCASE`、`LV_FREE/LV_WATCH/LV_FIX` |
| `dev/gen.js` | **ランダム生成**：`GEN`（調整値）、`planMachine`（流れの型で計画）、`verifyMachine`（物理で成功確認）、`generateMachine`、`makePuzzle`（なおして ゴールの問題づくり）、`TRAY_Z` |
| `dev/ui.js` | 描画・カメラ・音・UI・編集操作・モード切り替え（`showHome`/`enterMode`/`showWatch`/`randomWatch`/`newPuzzle`/`genAsync`）・説明文（`HELP`/`HELP_SET`）・`window.__game` |
| `dev/build.sh` | 5つをつなげて `../index.html` と `test/test.html` を作る |

テストの準備：`dev/test` で `npm i cannon-es@0.20.0 three@0.169.0 playwright-core`。
- 数値：`t24`/`t25`/`t27`（レベル2/3/1、`lib.mjs`）、`t30`（生成の成功率と時間）、`t33`（問題づくり40通り×3段階）、`t39`（みるの5パターンを条件をずらして5回ずつ）。`t30`以降は `lib2.mjs`（gen.js も読む）。
- ブラウザ：`node shot.mjs s10.mjs`（れんしゅう〜つくる通し）、`node shot.mjs s11.mjs`（タイトル画面・みる・おまかせ・なおしてゴール）、`node shot.mjs s12.mjs`（スマホ横・縦、iPad横・縦の撮影）。

### ランダム生成のしくみ（gen.js）

- 流れの型：さか →（かべで90°曲がる／ばねで飛ばす（3方向）／ドミノ5まい×1〜2＋玉／玉に当てる）を3〜5だん → ゴール。まっすぐな道には てっきんを置くことがある。てっきん2こ以上なら6割でゴールにさく。
- 置き方は「速さと進む距離」の式で決める（`GEN.DECEL` は実際より大きめにして余裕を持たせる）。0.5マスの方眼で、パーツと玉の通り道が重ならないようにする。かべに当たると道が0.92横にずれる点も計算に入れている。
- 計画できたら `createFloorSim` で最後まで回し、条件を少しずらしても（eps 0 と 0.02）成功したものだけ使う。
- ブラウザでは `genAsync` で40msずつ区切って試す（画面が固まらない）。たいてい0.5秒以内、遅くても数秒。
- なおして ゴールでは、通り道を z≦14 に収めて作り、手前 z≈16.2 を「おきば」にする。抜いたままで成功してしまう問題は使わない。

### チートにしている所（遊びやすさ優先）

- 坂を下りきった玉は、高さごとに決まった速さにそろえる。
- ばねは、乗った玉を台の真ん中に置き直し、矢印の向きに決まった速さで打ち出す。
- かべは鏡のようにきれいに反射させる（速さ0.95倍）。
- 倒れたドミノが玉に当たると、倒れる向きの先にある玉だけを決まった速さ（3.5）で転がす。
- 床は転がり抵抗で一定に減速（`ROLL_DECEL`）。
- ゴールは近くの玉を吸い寄せる。一度も転がっていない玉は数えない。
- てっきんは当たり判定なし。玉が上を通ると鳴る。

## 3. 確かめたこと・確かめていないこと

### 確かめたこと

- 計算：れんしゅうレベル1〜3は以前と同じ結果。みるの5パターンは、条件をずらした5通りすべて成功。ランダム生成は、計画できたものの約9割が物理でも成功（合格したものだけ使う）。なおして ゴールは40通り×3段階すべて問題を作れ、答えどおりに戻せば必ず成功、抜いたままでは必ず失敗。
- ブラウザ（Playwright）：タイトル画面 → 各モード → 🏠 の行き来、みる5つとおまかせ3回の成功、なおして ゴールで実際のドラッグと↺で1こ戻して成功、れんしゅう〜つくるの通しクリア。JSエラーなし。

### 確かめていないこと

- 実機のiPad・スマホでの操作感、音、生成の待ち時間。
- スマホ横のゲーム画面は床が小さめ（下のパネルが高さの約4割を使う）。以前の版より大きくはしたが、さらに広げるならパネルの並べ方から見直す必要がある。
