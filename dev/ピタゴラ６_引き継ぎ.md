### 遊びの構成（いま）

画面の上にレベルのタブ（レベル1・2・3・じゆう）と「？」ボタンがある。

| タブ | 新しいパーツ | お題 | 使わないとダメな理由 |
|---|---|---|---|
| レベル1 | さか・かべ | さかの高さを変え、かべを斜めに置いてゴールへ | ゴールは玉の通り道の横。さかは場所固定（高さだけ変えられる） |
| レベル2 | ドミノ・たま | 赤い玉は途中で止まる。ドミノでつないで、置いた玉を押してゴールへ | 赤い玉だけでは届かない。ドミノはゴールに入れても数えない |
| レベル3 | ばね・てっきん | てっきんを2こ鳴らすとゴールの「さく」が開く。ばねで飛ばす | ゴールは最初からさくで囲まれ、「♪ 0/2」と表示されている |
| じゆう | 全部 | 好きに作る。最初はみほん（動く装置）が置いてある | — |

パーツ：さか（玉つき・高さ3段）、たま（3こまで）、かべ（1種類）、ドミノ、ドミノ5まい、ばね（強さ3段・15°きざみ）、てっきん（ドレミ…8音）、ゴール。
**かざぐるまは外した**（当たるたびに玉の飛び方が変わり、練習に向かないため）。

### 操作

- 下のパーツを押すと、空いている場所に出る → 指でドラッグ（0.5きざみ）。
- 選ぶと ↺ ↻（15°ずつ）、設定ボタン（高さ・強さ・音）、「けす」と、ひとこと説明が出る。
- 「スタート」→「時間」バーで巻き戻せる。「ゆっくり」「おいかける」あり。
- 視点はふだん固定。「視点」ボタンを押したときだけ、なぞって回せる（もう一度押すと戻る）。

## 2. ソースの場所と作業の仕方

`index.html` は、`dev/` の4つの部品をつなげたもの。**編集は `dev/` の部品で行い、`dev/build.sh` で `index.html` を作る**（直接 index.html を直してもよいが、そのときは部品も合わせて直す）。

| ファイル | 中身 |
|---|---|
| `dev/head.html` | HTMLの枠・CSS・説明画面（スマホ対応のCSSもここ） |
| `dev/sim.js` | `CFG`（調整値）、`BOARD`（床 28×18）、`PARTS`（パーツ定義と説明文）、`createFloorSim`（物理。Node でも動く） |
| `dev/levels.js` | `LEVELS`（お題・使えるパーツ・NEWの印）、`SAMPLE`（じゆうのみほん）、`FREE_EMPTY` |
| `dev/ui.js` | 描画・カメラ・音・UI・編集操作・`window.__game`（テスト用フック）・起動 |
| `dev/build.sh` | 4つをつなげて `../index.html` と `test/test.html`（CDNの代わりに node_modules を読む版）を作る |
| `dev/test/` | 数値検証（`lib.mjs` を読み込む `t24`=レベル2、`t25`=レベル3、`t27`=レベル1）とブラウザ操作テスト（`shot.mjs` + `s9.mjs`/`s10.mjs`） |

テストの準備：`dev/test` で `npm i cannon-es@0.20.0 three@0.169.0 playwright-core`。ブラウザテストは `node shot.mjs s10.mjs`（Chrome＋SwiftShader。描画が遅いのでクリックの待ち時間は長め）。

### 設計の決まりごと

- 物理は cannon-es 0.20.0（完全な3D）、描画は Three.js 0.169.0。
- 配置データは `layouts[level]`（`{type,x,z,rot,opt,lock}` の配列。x＝左右、z＝おく・手前）。変更のたびに物理とメッシュを作り直す。
- `lock`：`true`＝動かせない（🔒）、`'pos'`＝場所と向きは固定で設定だけ変えられる（レベル1のさか）。
- ゴールの `opt`＞0 なら「さく」つき（てっきんを opt こ鳴らすと開く）。
- 巻き戻しは記録 `rec[]`（物体ごとに位置3＋回転4）から写す。ばね・さく・てっきん・旗・紙ふぶきは「その出来事からの時間」だけで見た目が決まる。

### チートにしている所（遊びやすさ優先）

- 坂を下りきった玉は、高さごとに決まった速さにそろえる。
- ばねは、乗った玉を台の真ん中に置き直し、矢印の向きに決まった速さで打ち出す。
- かべは鏡のようにきれいに反射させる（速さ0.95倍）。
- 倒れたドミノが玉に当たると、倒れる向きの先にある玉だけを決まった速さ（3.5）で転がす。ドミノの後ろの玉は押さない。
- 床は転がり抵抗で一定に減速（`ROLL_DECEL`）。
- ゴールは近くの玉を吸い寄せる。一度も転がっていない玉（ゴールに置いただけの玉）は数えない。
- てっきんは当たり判定なし。玉が上を通ると鳴る。

## 3. 確かめたこと・確かめていないこと

### 確かめたこと（計算）

- レベル1：さか「たかい」＋かべ45°で30通り成功。かべなしではどの高さでも失敗。
- レベル2（ゴール x=22.5）：ドミノ2セット＋玉の置き方79通り中74通り成功。残りは玉が最後のドミノから遠すぎる置き方。玉だけ・ドミノだけは0。
- レベル3：てっきん2こ＋ばねの置き方162通り中75通り成功。ばねだけ（てっきんなし）は0。
- じゆうのみほん：重力などを少しずらした5通りすべて成功。

### 確かめたこと（ブラウザ）

- Playwright で、実際のタップ・ドラッグで レベル1〜3・じゆう を通しでクリア。失敗時の表示も確認。

### 確かめていないこと

- 実機のiPadとスマホでの動作・操作感、音。

## 4. 次にやること（ユーザーと決定済み）

### (1) 最初のページ（タイトル画面）を作る

- 上のレベル選びのタブと「？」を、ゲーム画面から外す。
- 最初のページに、モードを大きく・かわいく並べる（例：「れんしゅう（レベル1〜3）」「みる」「つくる」「なおして ゴール」）。
- ゲームが始まったら、ゲーム画面を大きく使う。ゲーム中は小さな「もどる（🏠）」だけを置く想定。
- **注意**：プロジェクト共通仕様（6. ゲーム説明画面）では「画面の隅に常に『？』」が必須。ユーザーの希望は上の「？」を消すこと。遊び方の説明は、タイトル画面や各モードの開始時に出すか、🏠の横に小さく残すかを、実装前にユーザーに一言確認するとよい。
- スマホ対応（`head.html` のスマホ用CSS）を壊さないこと。

### (2) モードを足す（おすすめの順番）

1. **B：完成品を何パターンか見る**（「みる」）。配置データをいくつか `levels.js` に用意し、切り替えて見る。どれも事前に計算で成功を確かめる。
2. **A：完成品をランダムに作る**。でたらめに置くと成功しないので、「さか → ドミノ → 玉 → ばね → てっきん → ゴール」などの**流れの型**を先に決め、順番・向き・距離・数だけをランダムにする。作るたびに画面に出さず `createFloorSim` を最後まで回して成功を確かめ、失敗なら作り直す（「つくっています…」を表示）。
3. **C：なおして ゴール**。Aで成功する完成品を作り、いくつかのパーツを抜いて床の端などにバラバラに置く。子どもが並べ直してゴールさせる。答えが必ずあるので「解けない問題」は出ない。抜く数で難しさを変える。

## 5. 進め方のメモ（このプロジェクトの共通ルール）

- 文体：「させていただきます」は使わず「いたします」。
